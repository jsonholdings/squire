# Squire A/B trial — 2026-09-13

First controlled measurement of squire's token savings (SPEC-OPEN-SOURCE.md step 2). Prior
numbers (`PILOT-RESULTS-2026-09-12.md`) were explicit that no such trial existed yet.

## Method

`scripts/ab_trial.py` runs a fixed, committed set of real workloads twice each:

- **RAW** — the command's own stdout+stderr, or the file's own bytes, unmodified.
- **SQUIRE** — the same command via `squire run --json --`, or the same file via
  `squire sum --json`.

Token counts are an **APPROXIMATION**: chars/4, the same heuristic `squire.py` and
`squire_report.py` already use and label as an estimate. `tiktoken` is **not installed** on
this workstation (checked this run: `python3.13 -c "import tiktoken"` fails), so no exact
tokenizer count is claimed anywhere below.

Backend: `qwen2.5:14b` via Ollama on the RTX 3090, confirmed running (`curl
localhost:11434/api/tags` returned it) before the trial. `SQUIRE_KEEP_ALIVE` was already warm
from prior use this session, so the ~75s cold-load was not observed on this run — that cost is
real but is NOT included in any number below (see Limitations).

Run: `python3.13 scripts/ab_trial.py --json`, wall time 44s for all 8 workloads.

## Fidelity

- **Exit code:** VERIFIED preserved on all 5 command workloads, including the deliberately
  broken one (`pytest ... test_definitely_not_a_real_test_xyz`, real pytest exit code 4,
  squire's JSON `exit_code` also 4).
- **Failing-identifier preservation:** VERIFIED for the one workload with a known, injected
  failure signature (the bogus test node id) — but that workload's raw output was only 608
  chars, under squire's SHORT=60-line threshold, so squire passed it through **raw, unmodified**
  (0% saved). This trial did **not** produce a real, naturally-occurring long-output failure to
  test whether the LOCAL MODEL'S SUMMARY (not raw passthrough) preserves a failing test name —
  that is an **UNKNOWN**, flagged as a gap below, not claimed as verified.

## Control

`pytest -q` (3 lines raw) is included specifically to test squire's SHORT=60-lines passthrough
rule. Result: 0.0% saved, raw and squire chars identical (179=179), exit code preserved. This is
the expected behavior — a check on the checker — not a defect.

## Limitations (stated, not omitted)

- **UNKNOWN: main-Claude-session re-read cost.** This trial measures squire's own output vs.
  raw output for one read. It does NOT measure the `cache_read` amplification across a session's
  remaining turns that `squire_report.py`'s ESTIMATE layer models — that number stays ASSUMED
  and unverified by this trial.
- **UNKNOWN: cold-model load cost (~75s).** The backend was already warm this run. A first-call
  latency cost is real (per memory `squire_local_offload`) but not amortized into any %-saved
  figure here, which is a token measure, not a latency measure.
- **UNKNOWN: summary fidelity under a genuine, longer failure.** All 5 commands in this trial
  either passed or failed short. No workload exercised squire's model-generated failure summary
  (>60 lines AND a real failure) to check whether it names the right failing test. Next trial
  should add one (e.g. temporarily broken assertion in a scratch test file, reverted after).
- **n=8 is small and workload-specific to this repo.** Percent saved will vary by how
  repetitive/compressible the raw text is; squire.py itself compresses further (98.2%) than a
  test log (67.1%) because source code has more structural redundancy for a summarizer to drop.
- **Approximate tokenizer.** chars/4 is a rough proxy for English text and code; a real
  tokenizer (tiktoken/similar) was not available to cross-check on this workstation this run.

## Fidelity mode — closing the summary-fidelity UNKNOWN

The gap above ("summary fidelity under a genuine, longer failure") was untested: no workload
in the first pass triggered squire's actual model-generated summary path (>60 lines AND a real
failure). `scripts/ab_trial.py --fidelity` closes it with 6 synthetic-but-real subprocess runs
(each is `python3 -c "print(<text>); sys.exit(<code>)"`, so squire wraps a genuine subprocess,
not a canned string), each shaped like pytest `-v` output (PASSED/FAILED lines + a FAILURES
section), all >60 lines so they exercise the SHORT-threshold model-summarization path, not raw
passthrough. Failing test node ids are KNOWN (injected) and varied in position (early/middle/
last/scattered) and density (1-3 failures; one case buries a single failure in 220 lines of
passing noise). A control case injects zero failures and must come back clean.

Run: `python3.13 scripts/ab_trial.py --fidelity --json`, backend already warm (qwen2.5:14b
confirmed via `curl localhost:11434/api/tags` before the run).

| id | lines | exit match | injected failures | recall | false positive (control) |
|---|---:|---|---|---:|---|
| fidelity_early_single | 90 | yes | test_broken_login_flow (pos ~3%) | 100% | n/a |
| fidelity_middle_double | 101 | yes | test_price_rounding_bug, test_refund_race_condition (~45%/55%) | 100% | n/a |
| fidelity_last_single | 95 | yes | test_export_csv_encoding (~95%) | 100% | n/a |
| fidelity_multi_scattered | 112 | yes | test_auth_token_expiry, test_webhook_retry_backoff, test_cache_invalidation_edge (5%/50%/90%) | 100% | n/a |
| fidelity_mostly_pass_noise | 220 | yes | test_currency_conversion_rare_path (1 failure in 220 lines) | 100% | n/a |
| fidelity_control_all_pass | 89 | yes | (none) | n/a | **no** |

**VERIFIED, this run:** exit-code match rate **6/6 (100%)**; mean failing-test-name recall
across the 5 non-control cases **5/5 (100%)**, min recall 100% (no case missed a single
injected name, regardless of position or how much passing noise surrounded it); the all-pass
control did **not** fabricate a failure (`false_positive_on_control: False` — its summary
contained no "FAILED" token and no invented failing test name).

**What this does and does not close:** it closes the UNKNOWN for pytest-`-v`-shaped output on
this workstation, this run, with qwen2.5:14b, at these failure densities/positions. It is a
single run (n=6 cases, one pass each) — a flaky-model concern (does the LLM ever drop a name on
a *different* sample) is not ruled out by one pass, and non-pytest failure formats (compiler
errors, linter output, stack traces without a FAILURES section) are untested. No BACKLOG entry
was added: recall was 100%, so there is no defect to record yet — a repeat run showing a miss
would warrant one (see the doc's existing UNKNOWN-tracking discipline).
